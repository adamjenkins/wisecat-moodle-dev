# What changed from Moodle 4.0 to 5.1

Read this when the plugin's current minimum is below 5.2 and you need to know what changed in 4.x, 5.0 and 5.1
on the way to the supported versions.

Sources: the root `UPGRADING.md` of the 5.3.0 tree (it carries the 4.5, 5.0, 5.1, 5.2 and 5.3 sections),
`public/admin/environment.xml` of the 5.3.0 tree (requirements of every release), and the moodledev.io release
notes (https://moodledev.io/general/releases). Read, not run. For 4.4 and earlier, read the `upgrade.txt` files
of that branch; this file names only what a port still trips over.

Since 5.2 a site must already be on 4.4 or later to upgrade (`<MOODLE version="5.2" requires="4.4">`), so a
plugin's upgrade steps older than its 4.4-era version run only on sites that upgrade through 4.4 first. Keep them
anyway.

## Requirements by release

| Moodle | PHP floor | PostgreSQL | MySQL | MariaDB | SQL Server | Oracle | Upgrade from |
|---|---|---|---|---|---|---|---|
| 4.5 | 8.1.0 | 13 | 8.0 | 10.6.7 | 14.0 | 19 | 4.1.2 |
| 5.0 | 8.2.0 | 14 | 8.4 | 10.11.0 | 14.0 | removed | 4.2.3 |
| 5.1 | 8.2.0 | 15 | 8.4 | 10.11.0 | 14.0 | - | 4.2.3 |
| 5.2 | 8.3.0 | 16 | 8.4 | 10.11.0 | 15.0 | - | 4.4 |
| 5.3 | 8.3.0 | 17 | 8.4 | 11.4.0 | 15.0 | - | 4.4 |

In every row the sodium extension and 64-bit PHP are required (`check_sixtyfour_bits`), and `max_input_vars` of at
least 5000 is checked at level "optional": a warning, not a block.

## 4.0 to 4.4

- **4.0**: Boost redesign (course index, secondary navigation, drawers, the "More" menu); course format output moved
  to classes under `classes/output/courseformat/` extending `\core_courseformat\output\local\...`;
  `\core_courseformat\base` replaced `format_base`. Formats written for 3.x need their output rewritten.
- **4.2**: external API classes moved to `\core_external\` (`external_api`, `external_value`, ...); context classes
  to `\core\context\course` and friends (old names remain aliases).
- **4.3**: the Hooks API (`\core\hook\manager`, `db/hooks.php`; MDL-74954).
- **4.4**: hooks that replace `lib.php` callbacks (`replaces_callbacks`, MDL-81180), so old output callbacks start
  emitting "should be migrated" notices; dependency injection via `\core\di` (MDL-80072).

## 4.5 (LTS)

- The routing engine (`\core\router`, MDL-81031): REST API routes and routed pages, attributes on controller methods.
- Upgrade notes move from `upgrade.txt` to `UPGRADING.md`, generated by the `upgradenotes` tool
  (https://moodledev.io/general/development/upgradenotes). Plugins may keep either format.
- The AI subsystem (`core_ai`, placements and providers, MDL-82627).

## 5.0

- Bootstrap 5 in Boost. Bootstrap 4 class names and `data-toggle` attributes keep working through a compatibility
  layer (`theme/boost/scss/moodle/bs4-compat.scss`, `theme_boost/bs4-compat` JS) that is scheduled for removal in
  6.0 (MDL-84465). Screen-reader helpers renamed (`.sr-only` to `.visually-hidden`, MDL-81825).
- Shared question banks became `mod_qbank` activity instances (MDL-71378); question code that assumed a course or
  category context for banks needs review. Importers and generators should write into a `mod_qbank` instance that
  they choose or create explicitly, not into the site-level default bank.
- Oracle support removed.

## 5.1

- **The `public/` directory.** The web server document root is `<moodle>/public`; core code and plugins live under
  it (`public/local/example`), while `vendor/`, `admin/cli/` and, from 5.3, `lib/bundles/` are at `$CFG->root`
  above it. `$CFG->dirroot` is the `public` directory. After an in-place upgrade, add-on plugins must be moved into
  `public/` by hand (https://moodledev.io/general/releases/5.1). Paths computed from `$CFG->dirroot` keep working;
  relative paths that climbed out of a plugin to reach core files need checking.
- `file_encode_url()` deprecated in favour of the `\core\url` factory methods (MDL-31071).
- `course/changenumsections.php` deprecated for `course/format/update.php` (MDL-85284); the course format
  `maxsections` setting and `get_max_sections()` deprecated, removal in 6.0 (MDL-84291).
- Many core classes renamed for autoloading (the table at the start of the `## 5.1` section of `UPGRADING.md`);
  old names keep working.

## 5.2 and 5.3

These are the supported versions; their notes are listed in the Version notes table of this skill's `SKILL.md`,
and the full 5.3 catalogue is the `moodle-5-3-changes` skill.
